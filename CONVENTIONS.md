# rustls provider crate conventions

The rustls provider crates (`rustls-provider-rustcrypto-pq`, `rustls-provider-libcrux-pq` and
any later ones) share one layout, one test method and a set of files kept byte-identical.
`rustls-provider-rustcrypto-pq` is the baseline: its copies of this file and of the shared
files are canonical.

## Shared files

Byte-identical in every provider crate:

| File | Contents |
| --- | --- |
| `CONVENTIONS.md` | this file |
| `src/hybrid.rs` | the draft-ietf-tls-ecdhe-mlkem combiner, over an elliptic-curve group and an ML-KEM group the provider already has |
| `src/testkit.rs` | the conformance checks against rustls's aws-lc-rs provider |
| `testdata/make.sh` | generates the test keys and certificates |
| `.github/workflows/ci.yml` | CI |
| `.gitignore` | build output and generated test keys |
| `LICENSE-MIT`, `LICENSE-APACHE` | license texts |

Change a shared file in `rustls-provider-rustcrypto-pq` first, then copy it unchanged to every
other provider crate, with the same commit message in each. If one crate needs something
different, generalize the shared file; don't fork it. Check from a sibling crate:

```sh
for f in CONVENTIONS.md src/hybrid.rs src/testkit.rs testdata/make.sh \
  .github/workflows/ci.yml .gitignore LICENSE-MIT LICENSE-APACHE; do
  cmp "$f" "../rustls-provider-rustcrypto-pq/$f"
done
```

## Crate shape

- Name: `rustls-provider-<backend>-pq`.
- Public API: `pub fn provider() -> rustls::crypto::CryptoProvider` with every cipher suite,
  key-exchange group and signature algorithm the crate implements. Nothing else is public.
- Key exchange order: hybrids (X25519MLKEM768, SecP256r1MLKEM768, SecP384r1MLKEM1024), then
  classical (X25519, P-256, P-384), then pure ML-KEM (512, 768, 1024). Omit what the backend
  lacks; keep the order of the rest.
- Modules: `aead hash hmac hybrid kx sign suites verify`, plus `testkit` and `tests` under
  `#[cfg(test)]`. `lib.rs` holds the crate documentation (algorithm summary and a usage
  example), `provider()` and the `SecureRandom`.
- `Cargo.toml`, fields in this order: `name`, `version`, `authors`, `edition = "2021"`,
  `rust-version = "1.89"`, `repository`, `description`, `license = "MIT OR Apache-2.0"`,
  `readme`, `keywords` (at most 5, including `rustls`, `tls`, `post-quantum`), `categories =
  ["cryptography", "network-programming"]`, and this `include` list:

  ```toml
  include = ["/src", "/testdata/make.sh", "/README.md", "/LICENSE-MIT", "/LICENSE-APACHE"]
  ```

- Dependencies: `rustls = { version = "0.23.45", default-features = false, features = ["std",
  "tls12"] }`. aws-lc-rs only as the test reference, through the dev-dependency `rustls = {
  version = "0.23.45", default-features = false, features = ["std", "tls12", "aws-lc-rs"] }`.
  Pin a pre-release dependency with `=`, and give the reason in a `Cargo.toml` comment and in
  the README's Status section.
- `Cargo.lock` is committed.

## Code

- Default rustfmt, no `rustfmt.toml`: `cargo fmt --check` is clean.
- `cargo clippy --all-targets -- -D warnings` is clean on stable.
- Unoptimized builds run on 2 MiB threads (the default for `std::thread::spawn`, tokio workers
  and the test harness): plain `cargo test` passes. Never move large keys by value; an ML-DSA-87
  expanded key is about 100 KiB and debug builds copy it on every move. Keep such values on the
  heap from construction.
- Malformed peer input and malformed keys return an error, never a panic. Where the backend
  panics on bad input, validate before calling it.

## Tests

- `src/testkit.rs` (shared) runs a provider against rustls's aws-lc-rs provider: key exchange in
  both roles, malformed key shares, signatures both ways, hashes, HKDF and the TLS 1.2 PRF,
  in-memory handshakes, HelloRetryRequest, resumption, key updates, tampered records and random
  inputs. Each check returns what it covered.
- `src/tests.rs` (per crate) asserts that each check covered exactly what the crate implements,
  so a check can't pass by testing nothing. It also tests what aws-lc-rs has no counterpart for
  (for example MLKEM512, SecP384r1MLKEM1024 against aws-lc-rs's components, and private-key
  decoding).
- Keys and certificates are generated by `testdata/make.sh` on the first run, never committed.
  It needs OpenSSL 3.5 or later; `OPENSSL` points at another binary. `PQC_TEST_ITERATIONS` sets
  the rounds of the random-input checks (default 200).
- `cargo test --release` and `cargo test` both pass.

## README

Sections, in order, after the title and introduction: Algorithms, Usage, Status, Tests, Minimum
supported Rust version, License. Status covers FIPS 140 validation, pre-release and 0.x
dependencies, open RustSec advisories in dependencies and what they mean for users, and audit
status. The License section is the standard Rust dual-license text.

## CI

`.github/workflows/ci.yml` runs on pushes to `main` and on pull requests:

| Job | Runs |
| --- | --- |
| `fmt` | `cargo fmt --check` |
| `clippy` | `cargo clippy --locked --all-targets -- -D warnings` |
| `msrv` | `cargo check --locked --all-targets` on the `rust-version` in `Cargo.toml` |
| `test` | `cargo test --locked --release`, then `cargo test --locked`, on macOS with Homebrew's OpenSSL |
| `package` | `cargo publish --locked --dry-run` |

All jobs pass before a change lands on `main`.

## Git

- Commit messages: Conventional Commits, `type: summary` or `type(scope): summary` (`feat`,
  `fix`, `docs`, `test`, `refactor`, `chore`), in the imperative, with a body that says why when
  the summary doesn't.
- Author `Calvin Forinash <forinash@proton.me>`, set in the repository's own git config
  (`git config --local user.email forinash@proton.me`).

## Benchmark wiring

In `pqc-bench-tls`, each provider is a thin `rustls-tools/providers/<name>` wrapper over the
crate as a git dependency pinned to a revision. A path dependency breaks the Docker build, which
copies only `rustls-tools/`.

## New provider crate checklist

1. Copy the shared files from `rustls-provider-rustcrypto-pq`; set the git author.
2. Write `Cargo.toml` as above.
3. Implement the modules on the backend; reuse `hybrid.rs` for the hybrid groups.
4. Write `src/tests.rs`: one test per testkit check, asserting the expected coverage, plus tests
   for what aws-lc-rs can't check.
5. Write the README with the sections above.
6. Run every CI job locally before the first push.
